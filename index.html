Inactive users

Members who haven't signed in to ArcGIS Online for more than a year, plus members created more than a year ago who have never signed in, with an estimate of the storage credits their content will cost over the next 12 months.

Storage credits are worked out the same way as on the "Storage by user" tab: Esri's feature, imagery and file storage types, attachments as file storage, and per-image fees for dynamic imagery layers.

Inactive users

Last sign-in comes from each member's account in ArcGIS Online. "Never" means the account has never been used to sign in. Storage (MB, now) is what the member's content uses today, and Credits, next 12 months estimates what it will cost if it stays the same size. Rates: feature storage 2.4 credits per 10 MB per month; file and imagery storage 1.2 credits per GB per month; dynamic imagery layers also have a daily per-image fee. Before removing an account, transfer or review its content: other maps, apps and members may depend on it. Inactive accounts may also still use a paid user type.

Storage types and rates follow Esri's Understand credits page. Feature storage (2.4 credits per 10 MB per month) is the data in feature layers hosted in ArcGIS Online. Each layer's reported size includes its attachments, so the measured attachment size is subtracted and counted as file storage instead. Views, location sharing layers and feature collections aren't feature storage. Settings such as Enable Sync, Keep track of changes, and optimized drawing make feature storage grow over time; that growth is included in the size ArcGIS reports for each layer. Imagery storage (1.2 credits per GB per month) is imagery layers hosted in ArcGIS Online. Each dynamic imagery layer also has a daily per-image fee: 10 credits/day for 1–10 images, 20 for 11–100, 40 for 101–1,000, 80 for 1,001–10,000, 160 for 10,001–100,000 and 320 above that. The app counts each layer's images (collection items or multidimensional slices) and multiplies the daily fee by 365. File storage (1.2 credits per GB per month) is everything else: StoryMaps and their uploaded media, attachments in hosted feature layers, files, web maps, feature collections and so on. The status dashboard lists hosted tile, scene and vector tile layers separately (Tile, Scene, Vector Tile), so the summary does too. Unclassified is the storage ArcGIS reports for a member (their storage usage) minus everything the scan placed in a type. It's priced as file storage; if it's really feature data, the real cost is higher. Sizes in MB = 1,048,576 bytes. Credits per year = monthly rate × 12, assuming sizes stay the same all year. The dashboard shows what was actually charged over a past period, including items that have since changed or been deleted, so expect small differences. Sizes come from each member's content list and item details (ArcGIS search doesn't report sizes). If you've run the Top StoryMaps scan, its measured StoryMap sizes are used. Not included: ArcGIS Notebooks workspace storage and fixed-price Premium Feature Data Store plans. For the official numbers, see the Storage tab of your organization's status dashboard.

Top 25 feature layers to review

Views (12 months) and Views (30 days) are the usage counts from each item's Usage tab. For a hosted feature layer, ArcGIS counts usage as requests to the layer: one map view can make several requests. They're read from ArcGIS Online's usage reporting; "n/a" means the count couldn't be read, and lifetime views are used for ranking instead. Lifetime views (numViews) is the item's own numViews value, read directly from the item when the scan ran; opening the item page adds to it. Est. credits / yr = feature data × 2.4 credits per 10 MB per month × 12, plus attachments at the file storage rate (1.2 credits per GB per month × 12). Attachments are measured and removed from the layer's reported size. Credits per view = estimated credits per year ÷ (views in the last 12 months + 1). Before deleting anything, check the item page's usage, the maps and apps that use it, and with its owner. Consider exporting a backup first. Delete-protected items are marked.
